# PRD: 双人对战全流程 dev-browser 测试与中式8球合规验证

## Introduction

本 PRD 描述一个**测试驱动的修复工作流**：使用 dev-browser skill 在同一浏览器的两个标签页中模拟双人对战，
对游戏的完整生命周期（建房 → 开球 → 对战进行中 → 结算）进行逐阶段验证。

**核心原则：**
- 每个测试节点（Test Node, TN）是一个独立的阶段门（stage gate）
- 在当前节点记录所有发现的问题，即时修复，重测通过后才推进到下一节点
- 修复由 Claude 直接操作代码完成（非手动），修复后自动重测
- 最终目标：游戏行为与实际中式8球对战 100% 吻合

---

## Goals

- 使用同一浏览器两标签页完成完整一局双人对战的端到端验证
- 每个游戏阶段（4个）作为独立测试节点，发现问题记录 → 修复 → 重测
- 所有中式8球核心规则在真实浏览器交互下得到验证（而非仅单元测试）
- 修复过程不引入回归（现有 vitest 单元测试保持通过）
- 生成测试报告，记录每个节点的问题、修复内容、重测结果

---

## 测试环境约定

| 项目 | 说明 |
|------|------|
| 前端地址 | `http://localhost:5173` |
| Tab A | 模拟玩家1（创建房间方） |
| Tab B | 模拟玩家2（加入房间方） |
| 物理模拟 | 服务端 Matter.js，客户端仅渲染 |
| 超时机制 | 每回合 60 秒，最后 10 秒红色警告 |

---

## 中式8球核心规则参考（测试基准）

> 所有测试节点的判断依据

| 规则 | 标准 |
|------|------|
| 开球方 | 任意一方开球，开球后若进球则继续回合 |
| 花色分配 | 开球后首次进球确定双方花色（实心/条纹），黑8不参与分配 |
| 进球继续 | 合法进己方花色球后，当前玩家继续回合 |
| 换人条件 | 犯规 / 未进球 / 进对方球（仅换人，不是犯规） |
| 犯规条件 | ① 白球进袋 ② 首接触非己方球（含开台后分组完成时） ③ 无有效击打（无球碰库且无球进袋） ④ 己方球未清时打黑8 |
| 犯规后处理 | 对方在**全台**任意位置手放白球（不限半场） |
| 黑8制胜 | 己方球全部进袋后，合法击打并进黑8即获胜 |
| 黑8输局 | 己方球未清时进黑8 / 白球同回合进袋时进黑8 |

### TN-002: 开球阶段规则验证

**Description:** As a QA engineer, I want to verify that the break shot follows Chinese 8-ball rules, including ball assignment timing and turn continuation.

**测试步骤：**
1. 在 Tab A（玩家1）执行开球（拖拽白球 → 释放击打三角阵型）
2. 观察球运动和停止后的状态
3. 执行多种开球场景：进球 / 未进球 / 白球进袋

**子场景 A — 开球进球（最常见）：**
- 开球后至少一颗彩球进袋
- 预期：开球方继续回合，花色尚未分配（仍为 unassigned）
- 预期：花色在本局**首次进球**时分配（开球进球即立即分配）

**子场景 B — 开球未进球：**
- 开球后所有球均未进袋，但有球碰库
- 预期：换手给玩家2，无犯规

**子场景 C — 开球白球进袋（犯规）：**
- 预期：判犯规，玩家2 可在全台手放白球

**Acceptance Criteria:**
- [ ] 开球后进球，当前玩家继续回合（界面显示仍为玩家1的回合）
- [ ] 开球后花色分配在正确时机发生：首次进球时分配，而非提前
- [ ] 开球未进球 → 换手，无犯规提示
- [ ] 开球白球进袋 → 犯规提示出现，对方获得手放白球权（全台高亮）
- [ ] 全台手放白球：高亮区域覆盖整个台面（非半场）
- [ ] 截图存档每个子场景

**问题记录区（执行时填写）：**

### TN-003: 对战进行中 - 核心规则验证

**Description:** As a QA engineer, I want to verify all in-game rules work correctly during an active match, covering turn mechanics, fouls, and special cases.

**子场景 A — 进己方球继续回合：**
- 玩家进入己方花色球后，回合**不换人**
- 继续进球 → 继续不换人
- 预期：换人仅发生在犯规或未进任何球时

**子场景 B — 无有效击打犯规（无库犯规）：**
- 以极小力击打，白球轻触一颗球但两者均未碰库、均未进袋
- 预期：判犯规，对方手放白球

**子场景 C — 首次接触错误球犯规：**
- 白球首先碰到对方花色球（非己方）
- 预期：判犯规（即使最终有己方球进袋也是犯规）

**子场景 D — 进对方球不犯规但换人：**
- 白球首触己方球，但最终进了对方花色球
- 预期：不犯规，但换手（对方继续，对方球已进袋不归还）

**子场景 E — 白球进袋犯规：**
- 打球后白球进袋
- 预期：犯规，对方全台手放白球，重新放置白球后继续

**子场景 F — 犯规后全台手放白球验证：**
- 犯规触发后，验证对方可以在台面任意位置放置白球
- 点击台面靠近对方半场区域
- 点击台面靠近己方半场区域
- 预期：两处均可放置（非半场限制）

**子场景 G — 60秒倒计时：**
- 观察回合计时器是否从 60 开始倒数
- 等待至剩余 10 秒以内
- 预期：计时器变为红色警告样式
- 超时后预期：自动执行或换手

**Acceptance Criteria:**
- [ ] 进己方球后，回合状态栏显示仍为同一玩家的回合（TN-003-A）
- [ ] 无库犯规被正确检测并触发手放白球流程（TN-003-B）
- [ ] 首触错误球判犯规，即使己方球进袋也判犯规（TN-003-C）
- [ ] 进对方球时不犯规但换手（TN-003-D）
- [ ] 白球进袋触发犯规和全台手放白球（TN-003-E）
- [ ] 犯规后台面高亮覆盖全台（左右两侧均可点击放置）（TN-003-F）
- [ ] 倒计时正常运行，最后 10 秒变红（TN-003-G）
- [ ] 截图存档每个子场景

### TN-004: 结算阶段 - 胜负判定验证

**Description:** As a QA engineer, I want to verify all win/loss conditions are correctly handled when a player attempts to pocket the 8-ball.

**子场景 A — 正常获胜：**
- 玩家清空己方所有花色球后，合法击打并将黑8打进球袋

**子场景 B — 提前打进黑8输局：**
- 己方还有花色球未进袋时，将黑8打入球袋

## Functional Requirements

- FR-1: dev-browser 测试期间，服务端和客户端必须同时运行（`npm run dev:server` + `npm run dev:client`）
- FR-2: 每次 dev-browser 操作后必须截图，截图命名含节点编号和子场景（如 `TN-001-lobby-tabA.png`）
- FR-3: 发现 bug → 立即停止推进 → 读取相关代码 → 修复 → 运行 `npm run typecheck` + `vitest run` → 重新进行该节点的浏览器测试
- FR-4: 修复不得破坏现有单元测试（保持 vitest 通过）
- FR-5: 每个节点的「问题记录区」在测试完成后必须填写，即使没有发现问题也写「无」
- FR-6: 所有4个测试节点的问题记录汇总到 `tasks/test-report-two-player.md`

---

## 修复工作流（每个节点内部）

```
1. dev-browser 执行测试步骤
2. 截图记录当前状态
3. 发现问题？
   ├── 是 → 记录到问题记录区
   │         → 读取相关代码文件（server/gameLogic.ts, server/index.ts, client/BilliardTable.tsx）
   │         → 修复代码
   │         → npm run typecheck（确保无类型错误）
   │         → vitest run（确保单元测试通过）
   │         → 重新执行该节点的 dev-browser 测试
   │         → 截图记录修复后效果
   │         → 标记问题为「已修复」
   └── 否 → 标记该 Acceptance Criteria 为通过 [x]
4. 所有 AC 通过 → 节点完成 → 推进下一节点
```

## Non-Goals（范围外）

- 不测试3人以上房间
- 不测试网络断线重连
- 不测试移动端或触屏操作
- 不测试推杆犯规（push shot）
- 不实现开球"4球未碰库"的无效开球规则
- 不添加 Playwright 自动化框架（手动 dev-browser 操作）
- 不测试观战模式

## Technical Considerations

- **关键文件：**
  - `server/src/gameLogic.ts` — 规则判定核心
  - `server/src/index.ts` — WebSocket 事件处理、回合流转
  - `client/src/BilliardTable.tsx` — Canvas 渲染、手放白球 UI

- **已知待验证的历史修复（来自 prd-chinese-8ball-compliance.md）：**
  - US-012: 进球后继续回合（keepTurn）
  - US-013: 击打黑8的合法性
  - US-014: 全台手放白球（非半场）
  - US-015: 无库犯规检测

- **两标签页同步注意：** Tab A 和 Tab B 通过 WebSocket 共享同一个游戏状态，操作 Tab A 后需等待物理模拟结束（球停止运动），再在 Tab B 截图确认状态同步

- **dev-browser 操作要点：**
  - 击球通过在 canvas 上拖拽白球实现（从白球位置向相反方向拖拽）
  - 手放白球通过点击台面位置实现
  - 每次操作后等待 2-3 秒让物理模拟完成
